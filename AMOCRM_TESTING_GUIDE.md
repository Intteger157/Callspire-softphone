# Руководство по проверке модуля AmoCRM / Kommo

## Идентификация пользователя Kommo

Модуль определяет **пользователя Kommo, который совершает звонок**, по токену приложения:

- В настройках софтфона указываются **URL (поддомен)** и **Access Token** Kommo.
- По документации Kommo API: токен привязан к пользователю. При запросе `GET /api/v4/account` в ответе приходит **current_user_id** — это и есть пользователь Kommo, «владелец» токена.
- Модуль сохраняет этот ID при инициализации и при обработке звонка ищет **только среди лидов, назначенных на этого пользователя** (фильтр `filter[responsible_user_id][0]=current_user_id`).

**Важно:** чтобы запись разговора и карточка недозвона прикреплялись к «своим» сделкам, каждый пользователь софтфона должен использовать **свой токен Kommo** (токен того пользователя Kommo, от имени которого он звонит). Тогда модуль автоматически ищет контакт по номеру и сделку среди лидов, назначенных на этого пользователя, и прикрепляет запись к этой сделке.

## Подготовка к тестированию

### 1. Настройка AmoCRM / Kommo интеграции

1. Откройте **Настройки** → **Integrations**
2. Включите **"Включить интеграцию с AmoCRM"**
3. Заполните:
   - **Поддомен / URL**: ваш поддомен (например, `mycompany` для `mycompany.amocrm.ru` или `mycompany.kommo.com`)
   - **Access Token**: токен доступа Kommo **для того пользователя, который совершает звонки с этого софтфона** (получается в настройках интеграций Kommo)
4. Нажмите **"Сохранить настройки AmoCRM"**

### 2. Проверка инициализации

После сохранения настроек проверьте логи приложения:

**Ожидаемые сообщения в логах:**
```
[AmoCrmService] Drive URL loaded: https://drive-*.amocrm.ru
[AmoCrmService] Current user ID loaded: <число>
```

Если этих сообщений нет, проверьте:
- Правильность поддомена
- Валидность Access Token
- Наличие прав у токена (нужен доступ к файлам)

## Способы проверки

1. **Убедитесь, что в AmoCRM есть контакт с телефоном**, который вы будете использовать для звонка
2. **Убедитесь, что у этого контакта есть связанный лид (сделка)** - это обязательно, так как новые лиды не создаются
3. **Совершите звонок** (входящий или исходящий) на этот номер
4. **Дождитесь завершения звонка** (минимум несколько секунд)

2. Или найдите файл логов (обычно в папке приложения)

## Типичные проблемы и решения

### Проблема: "Contact not found"

**Причина:** В AmoCRM нет контакта с таким номером телефона

**Решение:**
1. Создайте контакт в AmoCRM с нужным номером телефона
2. Убедитесь, что номер телефона в формате, который использует AmoCRM
3. Проверьте, что номер нормализуется правильно (код убирает все кроме цифр)

### Проблема: "Лид для контакта не найден"

**Причина:** У контакта нет связанного лида (сделки) в AmoCRM

**Решение:**
1. **Важно:** Модуль не создает новые лиды, работает только с существующими
2. Создайте лид (сделку) в AmoCRM и привяжите его к контакту
3. Убедитесь, что лид активен (не в статусе "Закрыта" или "Успешно реализована", если это мешает поиску)
4. После создания лида повторите звонок

### Проблема: "Drive URL not loaded"

**Причина:** Не удалось получить `drive_url` из аккаунта

**Решение:**
1. Проверьте правильность Access Token
2. Убедитесь, что токен имеет права на доступ к файлам
3. Проверьте подключение к интернету
4. Попробуйте пересохранить настройки AmoCRM

### Проблема: "Failed to upload file"

**Причина:** Ошибка при загрузке файла

**Решение:**
1. Проверьте размер файла (не должен превышать лимиты AmoCRM)
2. Проверьте формат файла (должен быть MP3)
3. Проверьте логи для детальной ошибки
4. Убедитесь, что файл существует и доступен для чтения

### Проблема: "Failed to add call note"

**Причина:** Ошибка при создании примечания

**Решение:**
1. Проверьте, что `current_user_id` загружен (должно быть в логах при инициализации)
2. Проверьте права токена на создание примечаний
3. Проверьте формат данных в логах

### Проблема: Файл загружен, но кнопки "Прослушать/Скачать" не отображаются

**Причина:** Не передан `link` в `params` примечания звонка

**Решение:**
1. Проверьте логи - должно быть сообщение "Adding call note with link: ..."
2. Если ссылки нет, проверьте, что `download.href` был получен после загрузки файла
3. Убедитесь, что используется правильный формат примечания `call_in`/`call_out`

## Дополнительная диагностика

### Включение детального логирования

Все операции уже логируются. Для более детальной диагностики проверьте:

1. **HTTP запросы/ответы** - в логах есть статус коды и части ответов
2. **Размеры файлов** - проверьте, что файлы не слишком большие
3. **Время выполнения** - операции выполняются асинхронно, не блокируют UI

### Проверка в AmoCRM API напрямую

Если нужно проверить API напрямую:

1. Используйте Postman или curl
2. Проверьте эндпоинты:
   - `GET /api/v4/account?with=drive_url`
   - `GET /api/v4/contacts?query=<номер>`
   - `POST /api/v4/leads/complex`
   - `POST /api/v4/leads/{id}/notes`
