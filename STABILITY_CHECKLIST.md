# Чеклист стабильности для 100+ звонков в день

> **Как использовать:** Отмечайте галочками (☐ → ☑) выполненные тесты. Сохраняйте этот файл для отслеживания прогресса.

## Выполненные оптимизации

### 1. Оптимизация освобождения ресурсов
- ✅ **Аудио эндпоинт переиспользуется** между звонками (не закрывается при Hangup)
- ✅ **Медиа-сессия пересоздается** для каждого нового звонка (закрывается при Hangup)
- ✅ **Рекордер освобождается** сразу после остановки записи
- ✅ **Файловые потоки закрываются** с Flush() перед Dispose()

### 2. Улучшенная обработка ошибок
- ✅ Все критические операции обернуты в try-catch
- ✅ Ошибки логируются, но не приводят к падению приложения
- ✅ Ресурсы освобождаются даже при ошибках

### 3. Проверка инициализации
- ✅ Аудио эндпоинт проверяется перед переиспользованием
- ✅ Медиа-сессия пересоздается только при необходимости
- ✅ Добавлены проверки на null перед использованием

## Что проверять в логах

### ✅ Успешная инициализация (это нормально):
```
[SipService] Audio initialized successfully
[SipService] Media session reinitialized for new call (audio endpoint reused)
[WebRTC] ✓ Successfully registered on ATS server
[MainWindow] UpdateConnectionStatus: Status changed to 'Connected with WebRTC'
```

### ⚠️ Проблемы (требуют внимания):
```
[SipService] Error reinitializing media session
[SipService] Audio endpoint cannot create media endpoints
[RtpCallRecorder] Error closing PCM files
[WebRTC] ✗ Registration failed
[MainWindow] ERROR in ...
```

### 🚨 Утечки памяти (тревожные признаки):
- Постоянный рост памяти в Task Manager (память растет с каждым звонком)
- Множественные сообщения "Media session reinitialized" (должно быть редко)
- Ошибки "Out of memory"
- Приложение становится медленнее после множества звонков

### 📝 Как проверить логи:
1. Откройте **Log Window** в приложении (кнопка с документом в левом меню)
2. Или проверьте файл логов (если настроено логирование в файл)
3. Ищите строки с `ERROR`, `WARNING`, `Exception`
4. Обратите внимание на повторяющиеся ошибки

## Критические моменты

1. **Аудио эндпоинт НЕ закрывается** при Hangup - это нормально и оптимизировано для переиспользования
2. **Медиа-сессия пересоздается** для каждого звонка - это правильно
3. **Рекордер освобождается** сразу после остановки - предотвращает утечки
4. **Задержка 200ms** при переинициализации - дает время на закрытие предыдущей сессии

## Если возникают проблемы

1. **Проверить логи** на ошибки инициализации аудио (откройте Log Window)
2. **Проверить аудиоустройства** - не заняты ли они другим приложением (Skype, Teams, и т.д.)
3. **Перезапустить приложение** - полная переинициализация часто решает временные проблемы
4. **Проверить настройки** - убедитесь, что выбранные микрофон/динамик доступны
5. **Проверить сеть** - для SIP/WebRTC нужен стабильный интернет
6. **Проверить версии библиотек** - SIPSorcery и SIPSorceryMedia.Windows должны быть актуальными
